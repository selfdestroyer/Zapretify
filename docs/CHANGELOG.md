# Changelog

All notable changes to the Zapretify project are documented in this file.

## [1.4.1] - 2026-10-23

### Обновление баз Flowseal
- **Подробный отчёт вместо счётчиков.** После «Обновить базы» вместо «обновлено 22 стратегии и 5 листов» показывается, что изменилось на самом деле: какие стратегии добавлены, у каких изменились аргументы, какие списки обновились и сколько записей в них добавлено/удалено. Если upstream не менялся — «Файлы актуальны: изменений нет».
- Списки и `strategies.json` перезаписываются только при реальных изменениях.
- `ipset-all.txt` сравнивается с резервной копией, когда в файле стоит заглушка режима IPSet, поэтому он больше не считается изменённым при каждом обновлении.
- При частичной ошибке показываются и найденные изменения, и файлы, которые не удалось скачать.
- В ответ `/api/updater/assets/status` добавлены поля `changes`, `changed`, `added_strategies`, `updated_strategies`.

## [1.4.0] - 2026-10-19

### Новый интерфейс
- **Компактное окно 720×380** вместо 1060×700. Размер считается по клиентской области с учётом масштаба Windows (125–200%): раньше на таких масштабах окно было меньше макета. При переносе на монитор с другим масштабом окно пересчитывает размер, при запуске центрируется.
- **Один главный экран** вместо вкладок и боковой панели: общий статус, кнопка «Включить всё / Остановить всё», переключатели Zapret и Telegram-прокси, быстрые действия «Открыть в Telegram» и «Скопировать ссылку».
- **Настройки Zapret и Telegram — в окнах-диалогах**: стратегия с кнопкой «Проверить», служба Windows, Game Filter и порты, IPSet; порт и ключ прокси, замер задержки до дата-центров. Несохранённые изменения подсвечиваются, «Сбросить» требует подтверждения.
- **Подбор стратегий заново**: живая таблица лидеров, оценка оставшегося времени, итог с разбивкой по YouTube / Discord / прочему, список всех результатов, проверка одной стратегии по целям, кнопка «Остановить». Во время подбора главный экран показывает «Подбор · N из M».
- **Отдельные экраны** «Списки доменов», «Диагностика и сброс», «Журнал событий» (фильтр по уровню, автопрокрутка, красная точка при новых ошибках) и «Обновления».
- **«Настройки приложения»**: автозапуск Zapretify и запуск свёрнутым в трей вынесены из настроек Zapret, чтобы не путать их со службой Windows.
- Аварийные действия и очистка журнала подтверждаются повторным нажатием вместо системного окна `confirm()`.

### Списки доменов
- По умолчанию редактируются **свои списки** (`list-general-user.txt`, `list-exclude-user.txt`, `ipset-exclude-user.txt`) — их не трогает «Обновить базы». Файлы из базы Flowseal показываются только для просмотра.
- «Быстро добавить» принимает ссылку целиком (`https://www.site.org/page` → `site.org`), проверяет формат и дубли, добавление можно отменить.
- Пустой пользовательский список больше не ломает winws: при сохранении в него дописывается запись-заглушка.

### Telegram-прокси
- Адрес показан только для чтения (прокси принимает подключения только с этого компьютера), порт проверяется по диапазону 1024–65535.
- Секретный ключ скрыт по умолчанию, показать его можно кнопкой с глазом; после смены ключа есть подсказка заново добавить прокси в Telegram.

### Подбор стратегий (бэкенд)
- Новый маршрут `POST /api/zapret/benchmark-all/stop`.
- Итог подбора сохраняется в `last_benchmark.json` (`GET /api/zapret/benchmark-all/last`): «Прошлый подбор» и подсказка «Лучшая по подбору» переживают перезапуск.
- Досрочная остановка после трёх неудачных запусков winws подряд теперь действительно срабатывает (раньше условие было недостижимым).
- Остановленный подбор сохраняет отсортированные результаты и лучшую стратегию; стратегия без единого успеха имеет задержку `-1` («—»), а не «0 мс»; у результата есть признак `start_failed`.
- `/api/status` содержит поле `benchmark` (идёт ли подбор и сколько проверено).

### Запуск Zapret
- Перед запуском winws.exe приложение освобождает фильтр WinDivert: останавливает службу `zapret` (если она работает при выключенном режиме службы) и завершает оставшиеся `winws.exe` из своей папки `bin`. Раньше в этом случае новый процесс сразу закрывался с ошибкой «A copy of winws is already running with the same filter».
- Если фильтр держит `winws.exe` из другой папки (другая копия Zapret или похожая программа), выводится понятное сообщение с подсказкой «Диагностика и сброс → Завершить Zapret»; чужой процесс без согласия пользователя не завершается.

### Прочее
- Системные шрифты (Segoe UI, Cascadia Mono / Consolas) вместо загрузки Inter с Google Fonts: интерфейс одинаков без интернета, внешние источники убраны из CSP.
- У кнопок-иконок есть подписи для экранного диктора и всплывающие подсказки.

## [1.3.4] - 2026-10-19

### Безопасность
- **Локальный API установщика закрыт**: сервер установщика (`cmd/installer`) теперь проверяет заголовок `Host` (защита от DNS rebinding), `Origin`, `Referer`, `Sec-Fetch-Site` и случайный токен сеанса в `HttpOnly; SameSite=Strict` cookie. Мутирующие маршруты принимают только `POST`, тела запросов ограничены по размеру. Любая веб-страница в браузере больше не может управлять установщиком, работающим с правами администратора.
- **Нет интерполяции в PowerShell**: диалог выбора папки и создание ярлыков запускаются через `-EncodedCommand`, а пользовательские значения (`current_path`, пути ярлыков) передаются только через переменные окружения. Устранена инъекция команд через `/api/browse` и `createShortcut` и поломка при апострофе в имени пользователя.
- **Путь установки валидируется**: абсолютный путь, не корень диска, не папка Windows, без служебных символов.
- **Больше нет общего секрета Telegram-прокси**: `config.json` не входит ни в portable-архив, ни в установщик (`build_all.bat`, фильтр распаковки). Приложение создаёт конфигурацию при первом запуске со своим случайным секретом. Кнопка «Сгенерировать» в UI использует `crypto.getRandomValues` вместо `Math.random()`.
- **Завершаются только собственные процессы**: глобальные `taskkill /IM winws.exe` удалены из остановки/запуска/выхода/службы/установщика/деинсталлятора. Процесс `winws.exe` завершается по PID, а остатки прошлого сеанса (`winws.pid`) и процессы в `bin\` проверяются по полному пути образа (`platform.ProcessImagePath`). Глобальная очистка осталась только в явном «аварийном сбросе» (`/api/zapret/force-kill`).
- **Скачивание баз**: лимиты размера (8 МБ списки, 256 КБ `.bat`), отказ от пустых/не-200 ответов, атомарная запись, отклонение аргументов с управляющими символами.

### Целостность данных
- **`Zapretify.exe --uninstall` больше не делает `rd /s /q` для всей папки**: удаляются только известные файлы и подпапки (`bin`, `lists`, `assets`, `config.json`, …), сама папка — только если после этого пуста. Portable-копия в `Downloads`/`Desktop` не уничтожает чужие файлы. Ярлыки ищутся через known folders (учитывается OneDrive).
- **Обновление не затирает пользовательские данные**: `lists/*-user.txt`, `custom.txt` и `config.json` никогда не перезаписываются (создаются, только если отсутствуют). Любая ошибка распаковки теперь прерывает установку с понятным сообщением; защита от zip-slip.
- **Конфигурация**: `Load` нормализует секрет (hex, 32 символа), хост (loopback), режимы IPSet/game filter и порты; `Update` откатывает изменения, если валидация или запись на диск не удались; повреждённый `config.json` сохраняется как `config.json.bad`, а не молча сбрасывается.
- **`Registry.Find` строгий**: неизвестный ID стратегии больше не подменяется первой стратегией (ни в API, ни в службе, ни в бенчмарке). Для устаревшей стратегии из конфига используется явный `Registry.Default()`.

### Надёжность
- **Запуск `winws.exe` проверяется**: если процесс завершился в течение льготного периода, `Start` возвращает ошибку с последними строками его вывода; внешнее завершение процесса отслеживается.
- **Бенчмарк**: ошибки `runner.Start` учитываются (оценка 0, после 3 подряд — остановка с `error`), прежнее состояние (процесс или служба и стратегия) восстанавливается, во время бенчмарка запуск Zapret блокируется.
- **Автозапуск**: `SaveConfig` обращается к планировщику только при изменении настройки; состояние, созданное установщиком, отражается в UI; установщик регистрирует задачу планировщика, а ключ `Run` — только как запасной вариант (без двойного запуска).
- **Синхронизация upstream асинхронна**: `POST /api/updater/assets` сразу возвращает `{"status":"started"}`, результат — `GET /api/updater/assets/status` (UI опрашивает статус). Больше нет превышения `WriteTimeout`.
- Удалён неиспользуемый `PerformInPlaceUpdate`; консольные окна `net`/`sc`/`netsh` скрыты.

### Тесты
- Новые тесты: откат `config.Update`, нормализация секрета, `.bad`-копия конфигурации, строгий `Find`, жизненный цикл `ProcessRunner`/`CleanupOrphans`, защита API установщика (Host/Origin/токен), валидация пути, распаковка payload (user-файлы, zip-slip, отсутствие `config.json`), лимиты загрузки, асинхронная синхронизация, отказ для неизвестной стратегии. `TestLiveSync` запускается только при `ZAPRETIFY_LIVE_TESTS=1`.

## [1.3.3] - 2026-10-18

### Архитектура и внедрение зависимостей (Dependency Injection)
- **Устранение глобальных синглтонов в `app.go`**: в структуру `App` внедрены поля `cfg`, `runner`, `registry`, `tgServer`, а конструктор `NewAppWith` позволяет полностью изолировать компоненты в тестах без воздействия на глобальное состояние.
- **Модульность методов**: методы `App` обращаются к полям экземпляра, делая логику легко тестируемой и поддерживаемой.

### Асинхронный одиночный бенчмарк
- **Неблокирующий HTTP-запрос**: `POST /api/zapret/benchmark` теперь моментально возвращает `{"status":"started"}`, запуская процесс замера в фоне.
- **Опрос состояния через `GET /api/zapret/benchmark/status`**: фронтенд непрерывно опрашивает статус до завершения (`done: true`), полностью устраняя проблему обрыва HTTP-соединений и таймаутов браузера при длительных тестах.
- **Нормализация сетевых таймаутов**: `WriteTimeout` внутреннего HTTP-сервера возвращен к безопасным 60 секундам.

### Тестирование и контроль качества
- **Полноценный набор unit-тестов API (`api_test.go`)**:
  - Проверка строгого соблюдения HTTP-методов: все мутационные роуты возвращают `405 Method Not Allowed` на `GET`, а роуты чтения — на `POST`.
  - Валидация `/api/config`: тест на отказ при теле запроса > 1 МБ, отказ при наличии неизвестных полей JSON, корректное слияние частичных конфигураций.
  - Асинхронный жизненный цикл бенчмарка: запуск, статус, блокировка параллельного старта.
  - Защита списков: тест лимита 5 МБ при передаче данных в `/api/lists`.
- **Race Detector**: 100% тестов проходят с флагом `-race` без единой коллизии или предупреждения.

### Непрерывная интеграция (CI)
- **GitHub Actions Workflow (`.github/workflows/ci.yml`)**:
  - Автоматический запуск `go vet` и `go test -race` на каждый push и pull request.
  - Автоматическая компиляция бинарного файла Windows amd64 с генерацией `SHA256SUMS.txt` и сохранением артефактов сборки.

### Документация
- **Синхронизация `docs/ARCHITECTURE.md`**: спецификация REST API приведена в полное соответствие с кодом, документирована архитектура внедрения зависимостей (DI) и модель безопасности (CSRF, DNS Rebinding, токен сессии).

## [1.3.2] - 2026-10-18

### Безопасность и целостность данных
- **Потокобезопасный доступ к конфигурации**: метод `app.GetConfig()` возвращает изолированную копию (`Clone()`), а все модификации изолированы внутри `config.Get().Update(...)` под блокировкой мьютекса, исключая гонки данных.
- **Глубокая валидация и защита от инъекций**: введены проверки `GameFilterTCP` и `GameFilterUDP` (числовые диапазоны 1-65535, не более 16 диапазонов, запрет пробелов и флагов); санитизация аргументов в `BuildArgs` предотвращает внедрение параметров в командную строку `winws.exe`.
- **Обязательный секрет и валидация доменов**: запрещен пустой секрет Telegram-прокси; домены `CFWorkerDomain` и `CFUserDomain` валидируются как корректные hostname без схем и путей.
- **Фиксация источника обновлений**: репозиторий GitHub зафиксирован константой `DefaultGithubRepo = "selfdestroyer/Zapretify"`, предотвращая подмену источника бинарных обновлений через API.

### Списки и файловая система
- **Защита от зарезервированных имен Windows**: в `cleanPath` имя файла проверяется до первой точки, блокируя обход через `CON.foo.txt` и подобные DOS-устройства.
- **Белый список списков**: разрешены только доверенные стандартные списки и файлы пользователя `*-user.txt`.
- **Атомарная запись и лимит размера**: запись файлов списков переведена на временный файл с последующим переименованием (`temp+rename`) и жестким лимитом размера 5 МБ.

### Сеть и системные компоненты
- **Строгая валидация схем `tg://`**: разрешены исключительно безопасные хосты `proxy`, `resolve`, `join`.
- **Выгрузка WinDivert при установке и обновлении**: установщик (`Zapretify-Setup.exe`) и механизм in-place обновления принудительно останавливают и удаляют службу драйвера WinDivert, исключая ошибку блокировки `WinDivert64.sys`.
- **Контекст завершения сессий MTProto**: вызовы `handleClient` и циклы обработки получают контекст сервера и моментально прерываются при остановке.

## [1.3.1] - 2026-10-18

### Процессы и стабильность
- **Мониторинг winws.exe**: добавлена горутина `cmd.Wait()` в `core/zapret/process.go`. При сбое или внешнем завершении `winws.exe` статус в UI обновляется автоматически, очищается активная стратегия и удаляется PID-файл.
- **Безопасная зачистка орфанов (`CleanupOrphans`)**: перед `taskkill` проверяется имя исполняемого файла процесса (`winws.exe`), предотвращая завершение сторонних процессов при переиспользовании PID операционной системой.

### Telegram MTProto Прокси
- **Корректный парсинг секретов**: удаление транспортных префиксов `dd`/`ee` производится строго при длине 34 символа, сохраняя 32-байтные секреты.
- **Маскирование ключей в логах**: секрет скрывается в журналах как `dd1234***`.
- **Принудительный разрыв активных сессий**: при остановке Telegram-прокси все открытые клиентские соединения закрываются немедленно, предотвращая зависание Telegram.

### Конфигурация и миграция
- **Миграция старых конфигураций**: `config.Load()` автоматически исправляет и нормализует параметры старых версий (v1.2.2), предотвращая сбои валидации.
- **Синхронизация версии**: единая константа `config.Version = "1.3.1"` во всем проекте.

### Интерфейс (UI)
- **Обработка ошибок API**: все мутирующие операции используют обертку `api()` с проверкой `res.ok` и выводом сообщений об ошибках в тосты.
- **Поддержка F5 и sessionStorage**: токен сессии кэшируется в `sessionStorage`, предотвращая ошибку 401 при обновлении страницы; акселераторы F5/Ctrl+R перехвачены.

## [1.3.0] - 2026-10-17

### Стабильность и системные улучшения
- **Улучшенный запуск (Single Instance)**:
  - Проверка уже запущенной копии программы теперь выполняется до запроса повышения прав (UAC). Повторный запуск моментально разворачивает существующее окно приложения без всплывающих системных диалогов.
  - Исключен ошибочный захват окон проводника Windows с именем папки «Zapretify».
- **Изолированное управление процессами**:
  - Реализован точечный учет идентификатора процесса (PID) в `winws.pid`. Приложение завершает исключительно собственные процессы `winws.exe`, предотвращая случайное закрытие сторонних утилит (GoodbyeDPI, Flowseal).
  - Добавлен механизм автоматической зачистки фоновых процессов (`CleanupOrphans`) при следующем запуске в случае непредвиденного сбоя системы.
- **Инсталлятор и обновление**:
  - Мастер установки поддерживает режим бесшовного обновления поверх существующей версии с сохранением пользовательских списков и конфигурации `config.json`.
- **Надежность настроек**:
  - Применение списков IPSet теперь валидируется до сохранения в конфигурационный файл.
  - Добавлена проверка и корректная обработка ошибок при добавлении в автозапуск реестра Windows.

### Безопасность и API
- **Авторизация локального API**:
  - Добавлена проверка сессионного токена через заголовок `X-Zapretify-Token` с валидацией за константное время. Передача токена через URL отключена для предотвращения его попадания в системные журналы.
  - Добавлена строгая проверка заголовков `Host` и `Origin`, а также метаданных `Sec-Fetch-Site` для защиты от нежелательных межсайтовых запросов из браузера.
  - Маршруты изменения состояния переведены на метод `POST` с установкой лимита на размер входящих данных (1 МБ).
- **Валидация параметров и путей**:
  - Введена проверка стратегий и параметров тестирования по встроенному белому списку реестра.
  - В редакторе списков разрешены только файлы с расширением `.txt` внутри каталога `lists/` с блокировкой обращений к системным устройствам Windows (`CON`, `PRN`, `AUX`, `NUL` и др.) и потокам NTFS.
  - Открытие ссылок переведено на системный вызов Windows `ShellExecuteW` с проверкой доменных имен.
