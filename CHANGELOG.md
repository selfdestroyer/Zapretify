# Changelog

All notable changes to the Zapretify project are documented in this file.

## [1.2.3] - 2026-10-17

### ⚠️ ВАЖНОЕ ОБНОВЛЕНИЕ БЕЗОПАСНОСТИ (Security Advisory)
В версиях **1.2.2 и ранее** встроенный HTTP-сервер бэкенда (работающий с повышенными привилегиями администратора для взаимодействия с сетевым драйвером WinDivert) не осуществлял строгой проверки заголовков Origin/Host и не требовал обязательной аутентификации запросов через заголовки. Вследствие этого сторонние сайты, открытые в локальном браузере пользователя, гипотетически могли попытаться выполнить межсайтовые запросы (CSRF / DNS rebinding) к локальному порту `127.0.0.1`.

**Всем пользователям Zapretify версий 1.2.2 и ниже настоятельно рекомендуется обновиться до версии 1.2.3.**

---

### Безопасность и защита API (Security Hardening)
- **Криптографическая авторизация по заголовку (`X-Zapretify-Token`)**:
  - Генерация криптографически стойкого сессионного токена (256 бит) при каждом запуске.
  - Токен передается строго в HTTP-заголовке `X-Zapretify-Token`. Передача токена через query-параметр URL (`?token=`) полностью отключена во избежание утечки через логи, рефереры и историю браузера.
  - Проверка токена с использованием `crypto/subtle.ConstantTimeCompare` для исключения timing-атак.
  - Принцип *fail-closed*: все запросы к `/api/*` требуют токен; не-GET запросы к статике блокируются без токена.
- **Блокировка DNS Rebinding & CSRF**:
  - Строгая валидация заголовка `Host` (разрешен только локальный loopback интерфейс и порт экземпляра).
  - Строгая валидация заголовка `Origin` с блокировкой `Origin: null` (sandboxed iframe, `data:`, `file://`) и любых внешних источников.
  - Проверка метаданных запроса `Sec-Fetch-Site` (блокировка кросс-сайтовых запросов `cross-site`).
- **Защита методов и лимиты**:
  - Все мутирующие маршруты (`/api/zapret/benchmark`, `/api/zapret/open-test-log`, `/api/open-url`, `/api/zapret/ipset-mode`) переведены строго на метод `POST`.
  - Ограничение размера входящих тел запросов через `http.MaxBytesReader` (1 МБ) для защиты от DoS по памяти.
  - Маршрут `/api/config` клонирует текущую конфигурацию перед декодированием, исключая непреднамеренное обнуление полей при отправке неполных данных.
- **Санитизация путей и имен файлов списков**:
  - Полный запрет Path Traversal (`..`, `/`, `\`).
  - Разрешены только файлы с расширением `.txt`.
  - Блокировка альтернативных потоков данных NTFS (`:`).
  - Блокировка зарезервированных DOS-устройств Windows (`CON`, `PRN`, `AUX`, `NUL`, `COM1-9`, `LPT1-9`).
- **Безопасное открытие внешних ссылок (`/api/open-url`)**:
  - Белый список хостов (`github.com`, `telegram.org`, `t.me`) и схем (`http`, `https`, `tg`).
  - Открытие через нативный вызов WinAPI `ShellExecuteW` без передачи в командные оболочки (`cmd.exe`).
- **Порядок валидации IPSet**:
  - `SetIPSetMode` теперь сначала валидирует и применяет режим, и только при успехе сохраняет изменения в конфигурационный файл.
- **Обработка ошибок реестра**:
  - Метод `SaveConfig` теперь возвращает ошибку при сбое настройки автозапуска в реестре Windows.

### Стабильность и системные улучшения (Process & System Improvements)
- **Изолированное управление процессами без глобальных `taskkill`**:
  - Убраны агрессивные команды `taskkill /IM winws.exe` из бенчмарков и штатного завершения работы (`Shutdown`), предотвращая закрытие сторонних утилит (GoodbyeDPI, Flowseal и др.).
  - Добавлено сохранение PID процесса `winws.exe` в файл `winws.pid`.
  - Реализован механизм `CleanupOrphans`: при запуске программа корректно очищает «осиротевший» `winws.exe` от предыдущего аварийного завершения сеанса строго по сохраненному PID.
- **Улучшенный Single Instance без лишних UAC-окон**:
  - Проверка запущенного экземпляра до вызова самоповышения прав через `OpenMutex(SYNCHRONIZE)`. Если приложение уже работает, окно выводится на передний план, а повторный UAC-диалог не запрашивается.
  - Фильтрация окон проводника Windows (`CabinetWClass`, `ExploreWClass`) при поиске окна `Zapretify`.
