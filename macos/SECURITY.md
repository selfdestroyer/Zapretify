# Безопасность Zapretify для macOS

От root работает только служба `zapretifyd` (LaunchDaemon) и, до сброса прав, движок `utunws`.
Приложение (`Zapretify.app`, `zapretify-core`) работает от имени пользователя и root не получает.

## Модель угроз

Служба считает недоверенным всё, что приходит от пользователя: команды через сокет, `strategies.json`,
списки и файлы фейков в `~/Library/Application Support/Zapretify`. Вредоносная программа, запущенная
от имени этого же пользователя, может менять эти файлы как угодно. Служба не должна дать ей
ничего сверх того, что пользователь и так может: ни запуска своего кода от root, ни чтения или записи
чужих файлов.

## Что сделано

| Угроза | Защита | Где |
|---|---|---|
| Команды от чужого пользователя | Сокет `/var/run/zapretifyd.sock`, на каждое соединение проверяется uid собеседника (`LOCAL_PEERCRED`): только пользователь, установивший службу, и root | `server_darwin.go` |
| Подмена владельца службы | `daemon.json` принимается, только если принадлежит root и недоступен для записи другим | `cmd/zapretifyd` |
| Большие или бесконечные запросы | Запрос не больше 4 КБ, тайм-аут соединения 30 с | `server_darwin.go` |
| Произвольные опции движка от root (например `--debug=@файл`) | Белый список из 31 опции; движок запускается только с переведённой стратегией | `validate.go` |
| Пути за пределами папок службы | Пути только внутри `/Library/Application Support/Zapretify/{lists,bin}`, без `..`, только символы `A-Z a-z 0-9 пробел _ . / -` | `validate.go` |
| Подстановки в конфиге (`$VAR`, `*`, `~`, кавычки) — `utunws` разбирает `@файл` через `wordexp` | Такие символы запрещены в значениях и путях | `validate.go`, `CONTRACT.md` движка |
| Чтение чужих файлов через симлинки (root копирует файл, копия доступна всем) | Папка данных открывается по частям через `openat` с `O_NOFOLLOW`: ни папка, ни файл не могут быть симлинком | `importer.go` |
| То же через жёсткие ссылки | Каждый файл должен принадлежать пользователю службы | `importer.go` |
| Специальные и огромные файлы | Только обычные файлы, лимиты: стратегии 5 МБ, список 32 МБ, фейк 1 МБ; имена по шаблону | `importer.go` |
| Подмена системных утилит через `PATH` | `pfctl`, `ifconfig`, `route` и др. вызываются по полному пути | `engine_darwin.go` |
| Правила pf для чужого трафика | Перехват только портов стратегии, только трафика обычных пользователей (`user > root`), только на физическом интерфейсе (VPN не трогается); правила снимаются при остановке и падении движка | `validate.go`, `engine_darwin.go` |
| Движок от root дольше нужного | `utunws` после открытия интерфейса сбрасывает права до `nobody` (видно в журнале: `Running as UID=2147483647`) | движок Flowseal |
| Файлы службы | `/Library/Application Support/Zapretify`, plist, журнал — владелец root, запись только root; конфиг движка `/var/run/zapretify.conf` — 0600 | `install-daemon.sh` |
| Подмена движка при сборке | `utunws` собирается из закреплённого коммита форка, сборка приложения сверяет SHA256 из `engine.lock` | `build-app.sh` |

## Известные ограничения

- **Подпись.** Приложение подписано ad-hoc. Пока нет подписи Developer ID, macOS не может проверить,
  что файлы службы внутри `Zapretify.app` не изменены после сборки. Вредоносная программа с правами
  пользователя могла бы подменить их до установки службы (установка всё равно спрашивает пароль
  администратора). Решение — подпись Developer ID и нотаризация.
- **Отказ в обслуживании.** Любой локальный пользователь может открывать соединения к сокету; они сразу
  отклоняются, но не ограничены по количеству.
- Код движка `utunws` (C, около 17 тыс. строк, bol-van и Flowseal) нами не аудировался; он работает
  от root только до сброса прав.
